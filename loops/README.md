# Loop 工坊

用程式生成的音樂片段，像玩 loop station 一樣疊出你的歌。

- 五軌：鼓、貝斯、和弦、主旋律、效果音。每軌一次生成 8 段，每段 1、2 或 4 小節。
- 六種曲風：Lo-fi 嘻哈、浩室 House、合成器浪潮、流行搖滾、陷阱 Trap、8-bit 電玩。
- 所有聲音都用 Web Audio API 即時合成，沒有任何音檔，也不從網路載入任何東西。
- 純靜態網頁：不需要安裝、不需要打包。

## 怎麼開

整個遊戲就是 `loops/` 這個資料夾。用任何靜態網頁伺服器打開 `loops/index.html` 就能玩。

1. 進到 `loops/` 資料夾。
2. 啟動一個靜態伺服器，例如：

   ```bash
   python3 -m http.server 8080
   ```

   或用附的小伺服器（需要 Node.js）：

   ```bash
   node tests/serve.mjs 8080
   ```

3. 用瀏覽器打開 `http://localhost:8080/`。

不能直接雙擊 `index.html`（`file://`），因為瀏覽器不允許 `file://` 載入 JavaScript 模組。

發佈時把整個 `loops/` 資料夾放上任何靜態主機即可。所有路徑都是相對路徑，放在子目錄也能用。

## 怎麼玩

### 1. 生成片段

1. 在上方選一個曲風。
2. 按「生成新片段」：用種子欄裡的數字生成。
3. 按 🎲：換一個隨機種子，整批重新生成。
4. 每軌標題旁的 ↻：只重新生成那一軌。

同一批片段用同一個速度、同一個調。任意組合都合拍，和聲也不會打架。

種子顯示在畫面上。同一個曲風加同一個種子，一定生成一樣的片段。每一軌自己的種子顯示在軌道標題下面（例如 `#82527`）。

### 2. Loop 台

1. 點格子裡的片段：它排入佇列（虛線閃爍），在**下一個小節線**才開始播。
2. 每軌同時只播一段。點同一軌的別段，會在下一個小節線切換。
3. 點正在播的片段，或按該軌最下面的「■ 停止」：在下一個小節線停止。
4. 每軌都有 M（靜音）、S（獨奏）和音量條。
5. 正在播的片段會跟著拍子閃，底部的白線顯示播到片段的哪裡。
6. 上方的能量條跟著音樂跳動。

鍵盤快捷鍵（電腦）：空白鍵＝播放／停止，R＝錄音。

### 3. 錄下我的演奏

1. 按「錄音」。錄音在下一個小節線開始。
2. 照平常一樣切換片段。
3. 再按一次「停止錄音」。

錄下的過程會自動變成編曲裡的段落。同樣的組合連續播放的小節，會合併成一段。

### 4. 組成一首歌

到「編曲」分頁（電腦版在右邊）：

1. 用「新增段落」加入前奏、主歌、副歌、橋段、結尾。
2. 點一個段落，設定類型、長度（小節數），以及每軌用哪個片段（— 表示不用）。
3. 「▶ 播放整首」從頭播；「▶ 從這段播放」從選取的段落開始播。
4. 「一鍵排歌」會自動排一首 44 小節、五種段落都有的歌，可以當起點再修改。
5. Loop 台的「＋ 把現在的組合加成段落」：把正在播的組合直接加成一段。

### 5. 挑戰

「挑戰」分頁有 10 個徽章，例如：

- 完整的歌：做一首有前奏和副歌、至少 32 小節的歌
- 起承轉合：一首歌裡五種段落都有
- 現場演出：錄下至少 8 小節的演奏

完成時會跳出提示。徽章存在瀏覽器裡。

### 6. 匯出與存檔

到「檔案」分頁：

- 「匯出整首歌」：用 OfflineAudioContext 把整首歌算成 WAV（44.1 kHz、16-bit、立體聲）並下載。可以選擇結尾加 2 秒餘韻。
- 「存到瀏覽器」「從瀏覽器讀取」：存在 localStorage。
- 「下載專案檔」「開啟專案檔」：JSON 檔案，可以備份或分享。
- 「載入示範歌」：讀取 `examples/demo-project.json`。
- 每次修改都會自動暫存，重新整理頁面也會還原。

## 聲音設計

- 主輸出：高通 → 曲風音色濾波 → 壓縮器 → 限幅器 → 軟削波。軟削波的上限是 0.86（約 −1.3 dBFS），所以輸出不會破音。
- 各軌音量用離線算圖量過，再依曲風校正，讓五軌平衡。
- 殘響用程式產生的脈衝響應；延遲是附點八分音符，跟著速度變化。
- Lo-fi 有 16 分音符搖擺、人性化的時間誤差、錄音帶晃動和低通濾波。浩室和合成器浪潮有側鏈壓縮（大鼓踩下去時其他樂器讓一下）。

### 和聲為什麼不會打架

片段裡的音不是存成固定音高，而是存成「相對於當下和弦根音的調內音級」。

- 正在播的和弦片段決定現在的和弦。
- 貝斯、主旋律、效果音播放時，依當下的和弦換算成實際音高。
- 沒有和弦片段時，用這批片段的預設和弦進行。

所以不管怎麼組合，所有音都在同一個調裡，而且會跟著和弦走。

## 檔案結構

```
loops/
├── index.html          遊戲頁面
├── src/
│   ├── main.js         介面與遊戲流程
│   ├── engine.js       即時播放引擎（提前排程、量化、錄音）
│   ├── transport.js    量化排程的純邏輯
│   ├── generator.js    片段生成器
│   ├── genres.js       曲風預設
│   ├── theory.js       樂理（調式、和弦、配置）
│   ├── player.js       把一個小節變成聲音
│   ├── synth.js        所有音色（Web Audio 合成）
│   ├── mixer.js        混音台與主輸出
│   ├── render.js       離線算圖、匯出
│   ├── wav.js          WAV 編碼／解碼
│   ├── song.js         編曲、錄音轉段落、一鍵排歌
│   ├── project.js      專案存檔
│   ├── challenges.js   挑戰與徽章
│   ├── rng.js          有種子的隨機數
│   └── styles.css
├── vendor/             第三方套件（目前沒有用到）
├── screenshots/        手機與電腦的截圖
├── examples/           示範歌（專案檔＋WAV）
└── tests/              單元測試、端對端測試
```

## 測試

需要 Node.js 20 以上。

單元測試（量化排程、調內音、種子重現、錄音轉段落、存檔、WAV）：

```bash
npm test
```

端對端測試（Playwright 無頭瀏覽器）：

```bash
npm run e2e
```

端對端測試會：

1. 檢查頁面載入時 console 沒有錯誤（電腦 1366 寬、手機 375 寬）。
2. 用介面生成片段、點片段播放、錄音、排出三個段落、匯出 WAV。
3. 檢查 WAV 長度符合小節數、峰值低於 0 dBFS、不是靜音、每一軌分開算都有聲音。
4. 測試存檔：存到瀏覽器、下載專案檔再開啟、載入示範歌。
5. 把截圖存到 `screenshots/`，結果存到 `tests/e2e-report.json`。

最近一次結果：單元測試 22 項全部通過；端對端測試 37 項全部通過。匯出的 WAV 峰值約 −1.5 dBFS，沒有任何取樣點碰到滿格。

重新產生示範歌：

```bash
node tests/make-demo.mjs house 8080
```

## 已知的限制

- **iPhone 靜音模式**：有些 iOS 版本在靜音開關打開時，網頁不會發出聲音。遊戲已經用了常見的解法，但如果還是沒聲音，請關掉靜音模式。
- **背景分頁**：切到別的分頁或鎖定螢幕時，瀏覽器可能暫停或節流網頁的計時器，播放可能會斷斷續續。
- **小節線前的點擊**：引擎會提前 0.15 秒排程下一個小節。如果在小節線前 0.15 秒內才點，片段會排到再下一個小節。
- **匯出速度看裝置**：匯出是在瀏覽器裡算的。手機或舊電腦匯出一首 2 分鐘的歌，可能要幾十秒。
- **只在 Chromium 上自動測試過**：自動測試用的是 Playwright 的 Chromium。Safari（iOS 14.5 以上）和 Firefox 用到的功能都有支援，但沒有實機測試。
- **不同瀏覽器聲音略有差異**：同一個種子生成的音符完全一樣，但各瀏覽器的壓縮器、濾波器實作不同，音色細節會有一點差異。
- **段落裡的片段從段落開頭循環**：手動排的段落，每個片段都從段落第一小節重新開始。錄音產生的段落會記住接續位置。
- **存檔只在同一個瀏覽器**：清除網站資料會讓瀏覽器存檔不見。重要的歌請「下載專案檔」。
- **沒有音符編輯器**：片段只能生成，不能手動改音符。
- **合成音色**：沒有真實樂器取樣，全部是合成器聲音。
- **示範歌**：為了小於 10 MB，`examples/demo-song.wav` 只有 24 小節。
